# Вариант 28 для RV32I

`program.s` вычисляет `a_n = a + (n-1)*d`. Все входные данные и ответ
расположены в секции `.data`, которую при запуске нужно разместить в ОЗУ:

| Метка | Содержимое |
|---|---|
| `a` | Первый член, изначально 1 |
| `sw` | Упакованные d и n, изначально 0x0203 |
| `result` | 32-битный результат, для примера 5 |

`sw` — обычная переменная в ОЗУ. Значение переключателей теперь задаётся
через эту переменную, обращения к физическим переключателям нет.
Для другого примера измени `.word` у `a` и `sw` перед сборкой либо
соответствующие слова ОЗУ перед запуском программы.

Программа загружает входы через `lw`, выделяет `n` маской 255, а `d` —
логическим сдвигом на 8 и такой же маской. Затем прибавляет `d` к `a`
ровно `n-1` раз и сохраняет ответ инструкцией `sw`.
`mul` не используется: она относится к расширению M, а не к RV32I.
`la` — псевдоинструкция загрузки адреса метки, разворачиваемая ассемблером
в базовые инструкции; `.data`, `.text`, `.word`, `.align`, `.globl` — директивы.

Для `n=0` принято продолжение формулы: `a_0=a-d`, как описано в README
предыдущего решения. Условие задания не определяет этот случай отдельно.
Сложение и вычитание выполняются по модулю 2^32.

## Запуск в RARS

1. Открой `program.s`, выбери режим RV32 (RV64 выключен).
2. Нажми Assemble, затем выполняй программу пошагово либо поставь точку
   останова на `done` и нажми Go.
3. В Data Segment проверь слово с меткой `result`: для исходных данных это
   `0x00000005`. Метки можно посмотреть в Labels.

В конце выполняется бесконечный переход на `done`. Это ожидание после
сохранения результата. Для повторного запуска с новыми данными сбрось программу.
Системные вызовы и вывод в консоль не нужны.

| a | sw (hex) | d | n | result (hex) |
|---:|---:|---:|---:|---:|
| 1 | 0203 | 2 | 3 | 00000005 |
| 1 | 0201 | 2 | 1 | 00000001 |
| 1 | 8003 | 128 | 3 | 00000101 |
| 1 | FFFF | 255 | 255 | 0000FD03 |
| 1 | 0003 | 0 | 3 | 00000001 |
| 1 | 0200 | 2 | 0 | FFFFFFFF |

## Запуск на процессоре из лабораторных

Этот исходник нужно собрать под RV32I и разместить секции `.text` и `.data`
по адресам, принятым в конкретной системе. Память инструкций должна получить
машинный код, а ОЗУ — начальные значения секции `.data`. Начальный PC должен
указывать на `main`. Адреса меток определяет ассемблер/компоновщик.

Старый CyberCobra `program.mem` и этот ассемблерный исходник имеют разные
форматы. Для аппаратного запуска нужны отдельные образы инструкций и данных;
одного исходника, подключённого вместо `.mem`, недостаточно.

## Что уже есть в mpsis-labs и чего не хватает для Vivado

В `lab4` находится процессор CYBERcobra, в `lab5` — декодер RISC-V,
в `lab6` — отдельный модуль `data_mem`. Готового ядра RV32I и модуля
`processor_system` в этой папке пока нет. Их создание — содержание ЛР7
курса APS. Наличие ОЗУ само по себе не позволяет выполнить программу.

Для аппаратного запуска нужны:

1. `processor_core` RV32I: PC, регистровый файл, АЛУ, декодер,
   формирование immediate и логика переходов/загрузок/записей.
2. `processor_system`, соединяющий ядро, память инструкций и `data_mem`.
3. Загрузка машинного кода в память инструкций и начальных данных в ОЗУ.
4. Тестбенч с тактовым сигналом и сбросом, проверяющий результат в ОЗУ.

В вашей `lab6/rtl/data_memory.sv` чтение синхронное: значение появляется
после фронта `clk_i`. Ядро должно учитывать задержку чтения, даже несмотря
на постоянно установленный `ready_o=1`. В ЛР7 для этого предусмотрена
остановка PC на такт при обращении к памяти.

ОЗУ содержит 512 байт (128 слов). Например, при выбранном размещении данных
с нулевого адреса: a — байтовый адрес 0 (`ram[0]`), sw — 4 (`ram[1]`),
result — 8 (`ram[2]`). Это пример карты памяти для RTL, не адреса по умолчанию
в RARS. Адреса, которые выдаёт ассемблер, должны соответствовать карте системы;
усечение старших битов адреса в текущем модуле RAM не заменяет карту памяти.

Для примера перед снятием сброса в тестбенче можно установить
`dut.data_memory.ram[0] = 32'h00000001;`,
`dut.data_memory.ram[1] = 32'h00000203;`,
`dut.data_memory.ram[2] = 32'h00000000;`.
Здесь `dut.data_memory` — условный путь: заменить на имя реального экземпляра.
Инициализация выполняется до исполнения программы; сама программа читает
входы из ОЗУ через `lw`, затем записывает ответ через `sw`.
Для полноценного слова у RAM нужно `byte_enable_i=4'b1111`.

Для сдачи именно программы на ассемблере можно показать выполнение в RARS.
Если требуется демонстрация на собственной процессорной системе или плате,
нужно дополнительно выполнить аппаратную часть ЛР7.
