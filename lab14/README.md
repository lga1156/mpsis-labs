# Лабораторная №14 — высокоуровневое программирование

Основа — процессорная система lab13 с PS/2-клавиатурой и VGA.
Вариант 28 из ЛР4: a_n = 1 + (n − 1) × d.

## Работа программы

На PS/2-клавиатуре введи d цифрами верхнего ряда, нажми Enter,
затем введи n и нажми Enter. Оба параметра — от 0 до 255.
Результат появляется в четвёртой строке VGA-экрана. Можно сразу вводить
следующую пару. Лишние цифры и значения выше 255 игнорируются;
Backspace и цифровой блок не поддерживаются.

Пример: 2, Enter, 3, Enter → result= 5.
Первый член a=1 задан в программе. Для n=0 сохранено соглашение из ЛР4:
a_0=1−d; отрицательный результат выводится со знаком минус.

main очищает экран и выводит подсказки. int_handler считывает скан-код
PS/2, обрабатывает цифры и Enter, вычисляет результат и записывает символы
в VGA. Последовательности отпускания клавиш не вводят повторные цифры.
Доступ к периферии — через platform.h. Стандартный ввод-вывод и динамическая
память не используются.

## Файлы и сборка

- firmware/main.c — программа на C.
- firmware/startup.S — запуск и низкоуровневый обработчик прерывания.
- firmware/linker_script.ld — размещение кода, данных и двух стеков.
- firmware/platform.h — структуры регистров периферии из методички.
- firmware/disassembly.txt — дизассемблирование собранной программы.
- mem/init_instr.mem, mem/init_data.mem — готовые 32-битные образы памяти.
- tb/lab_14.tb_processor_system.sv — тестбенч из ЛР13 с изменённым вводом.

Для пересборки нужен GNU RISC-V toolchain с поддержкой rv32i_zicsr/ilp32:

```sh
./scripts/build_firmware.sh
```

Если компилятор не в PATH, задай полный префикс, например:

```sh
RISCV_PREFIX=/path/to/bin/riscv-none-elf- ./scripts/build_firmware.sh
```

Сборка создаёт result.elf и карту размещения в build/firmware,
обновляет образы памяти и дизассемблирование. Адрес загрузки данных
в ELF искусственный; скрипт переводит начало init_data.mem на нулевую ячейку.
.bss обнуляется при запуске, поэтому экспортировать её содержимое не требуется.

Сохранены фактические размеры памяти lab13: инструкции 4 КиБ, данные 16 КиБ.
Они больше минимума из методички (1 и 2 КиБ) и согласованы со скриптом
компоновки. В этой реализации memory_pkg отсутствует: размеры заданы
непосредственно в instr_mem.sv и ext_mem.sv.
В startup.S исправлена граница обнуления .bss (конец не включается),
а инициализация gp защищена от linker relaxation.

## Vivado

В Tcl Console укажи абсолютный путь к скрипту:

```tcl
source /path/to/lab14/scripts/create_vivado.tcl
```

Скрипт создаст проект для Nexys A7-100T в build/vivado,
добавит RTL, образы памяти, ограничения платы и существующий тестбенч.
Для моделирования: Run Simulation → Run Behavioral Simulation, время 16 ms.
Тестбенч вводит d=2 и n=3 с последовательностями отпускания клавиш.
Ожидаемое сообщение: PASS: a=1 d=2 n=3 result=5.

Для проверки на плате: выполнить синтез, реализацию, генерацию bitstream,
подключить PS/2-клавиатуру и VGA-монитор, запрограммировать Nexys A7-100T
через Hardware Manager и повторить ввод 2, Enter, 3, Enter.

## Выполненная проверка

Программа собрана GNU RISC-V GCC 13.2.0 без предупреждений C-компилятора.
Код — 1128 байт, инициализированные данные — 88 байт, .bss — 20 байт.
Существующий тестбенч выполнен в Verilator: PASS, в видеопамяти получен символ 5.
Для локального моделирования использовалась временная модель BUFG;
в Vivado этот примитив предоставляет UNISIM.
Синтез, моделирование в Vivado и физическая проверка на ПЛИС пока не выполнялись.
